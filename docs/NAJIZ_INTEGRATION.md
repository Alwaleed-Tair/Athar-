# دراسة التكامل المستقبلي مع منصة ناجز / Najiz integration study

**الحالة: دراسة فقط. لا يوجد في أثر أي اتصال بناجز ولا محاكاة له.**
**Status: study only. ATHAR has no connection to Najiz and does not simulate one.**

## 1. ما تم التحقق منه وما لم يُتحقق منه

| البند | الحالة |
|---|---|
| وجود واجهات API رسمية عامة لناجز لجهات خارجية | **غير مؤكد.** لم أتمكن من التحقق منه من بيئة التطوير، ولا أعرف توثيقاً عاماً يتيح للمطورين ربط تطبيق خارجي. يجب سؤال وزارة العدل رسمياً. |
| صلاحيات الوصول (حساب جهة، مفاتيح، اتفاقية) | غير متوفرة لدينا. عادةً تتطلب اتفاقية رسمية وتصريحاً للجهة. |
| قراءة بيانات ناجز بأدوات آلية (scraping) أو بيانات دخول المستخدم | **مرفوض.** مخالف للشروط وغير آمن ولا يُنفَّذ. |

لا تُنفَّذ أي ميزة تدّعي الاتصال قبل توفر وصول رسمي مكتوب.

## 2. المتطلبات التنظيمية المتوقعة (للتأكد منها مع الجهة)
- اتفاقية/ترخيص رسمي من وزارة العدل أو الجهة المشغِّلة، وتحديد نطاق البيانات المسموح بها.
- الامتثال لنظام حماية البيانات الشخصية (PDPL) ولوائح الأمن السيبراني (الهيئة الوطنية للأمن السيبراني): أساس نظامي للمعالجة، تقليل البيانات، التخزين داخل المملكة إن اشترط ذلك.
- موافقة صاحب العلاقة أو سند نظامي لكل عملية جلب، وتسجيلها.
- بيئة اختبار (sandbox) وبيانات اختبار من الجهة، لا بيانات حقيقية في التطوير.

## 3. المتطلبات التقنية المتوقعة
- مصادقة: غالباً OAuth2 / مفاتيح جهة / شهادات (mTLS) وربط بهوية المستخدم (نفاذ). يُحدَّد بحسب وثائق الجهة.
- تخزين الأسرار في متغيرات بيئة/خزنة أسرار، لا في الكود.
- معالجة حدود الطلبات، وإعادة المحاولة، وانتهاء الصلاحية.
- مراقبة وسجل تدقيق لكل استدعاء خارجي.

## 4. التصور المعماري (يسمح بالإضافة دون إعادة بناء)
مبدأ: **كل ما يأتي من ناجز يدخل عبر نفس مسار رفع الأدلة الحالي**، فيستفيد تلقائياً من حساب SHA-256 والتحقق من النوع وسجل العهدة وعزل المستخدمين.

```
backend/app/integrations/
    base.py        # واجهة مجردة: CaseSource.list_cases(), fetch_case(), fetch_documents()
    najiz.py       # (مستقبلاً) تنفيذ فعلي بعد توفر الوصول الرسمي
    registry.py    # يُفعَّل فقط إذا ضُبطت متغيرات البيئة الخاصة بالمزوّد
routers/imports.py # POST /api/cases/{id}/import/{provider}  (عضو في القضية فقط)
```
تدفق الاستيراد: المستخدم يربط حسابه بموافقة صريحة ← يختار قضية ناجز ← الخادم يجلب بيانات القضية والمستندات ← كل مستند يمر عبر `upload_evidence` نفسه (hash + تحليل + سجل عهدة) مع وسم مصدر `source = NAJIZ` ومعرّف المرجع الخارجي ← حدث `EXTERNAL_IMPORT` في سجل التدقيق.

تغييرات قاعدة البيانات المتوقعة: عمود `source` و`external_ref` في `evidence`، وعمود `external_case_ref` في `cases`، وجدول `integration_links` (المستخدم، المزوّد، حالة الموافقة، تاريخها).

## 5. بديل متاح اليوم دون أي API
المستخدم ينزّل المستندات من حسابه في ناجز يدوياً ويرفعها إلى أثر؛ أثر يحسب بصمتها ويحلل نصوصها كأي دليل آخر. هذا يعمل الآن ولا يحتاج اتفاقية.

## 6. الخطوات الموصى بها
1. مخاطبة وزارة العدل رسمياً لمعرفة وجود واجهات للجهات الخارجية وشروطها.
2. الحصول على بيئة اختبار ووثائق API.
3. تنفيذ `najiz.py` خلف الواجهة المجردة وإضافة اختبارات على بيانات اختبارية فقط.
